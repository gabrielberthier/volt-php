Sync vs async PHP, measured

The same SQL and the same CPU work, served two ways: PHP-FPM with blocking PDO, and an AMPHP event loop with non-blocking Postgres. Both servers get 2 CPUs. Async wins when PHP is waiting. It changes nothing when Postgres or the CPU is doing the work.

3.9×more requests per second while waiting on the database (/io, 64 users)
1.9×more requests per second on small indexed queries (/customer)
1.0×on heavy analytical queries (/report): Postgres is the limit
How they wait

A blocked process vs a suspended fiber

Each request runs a little PHP, waits 100 ms for Postgres, then runs a little more PHP. An FPM child can't do anything else during the wait, so 16 children means at most 16 requests in flight. An async worker parks the request's fiber, keeps serving other requests, and resumes it when the result arrives.

Concurrency ceiling · /io?ms=100

Sync tops out at 16 requests in flight

Throughput is in-flight requests ÷ 0.1 s. Up to 16 users the two servers are identical. Past that, sync stays at 152 req/s and every extra user just waits in the queue, so latency doubles each time users double. Async keeps going until it runs out of its 128 pooled database connections (2 workers × 64).

Inside one request · /regions

Three queries in a row, or three at once

/regions runs the heavy report for each of the three regions. Sync runs them one after another. Async starts all three and waits for the slowest, so one request finishes in about half the time.

Single request, nothing else running. Under load the speedup disappears: 8 users put 24 queries on Postgres with async instead of 8, and both servers end up at about 1 request per second, which is what Postgres can compute.

The real bottleneck · /report

Async can't make Postgres compute faster

One report query takes about 300 ms of Postgres CPU. Running them side by side, measured inside Postgres with no PHP involved, 4 CPUs finish about 3 per second. Both servers reached 2.4 req/s on /report. Once the database is saturated, the execution model no longer matters.
